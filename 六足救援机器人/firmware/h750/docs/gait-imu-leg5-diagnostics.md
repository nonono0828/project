# H750 六足步态、BMI088 与 Leg5 调试说明

## 1. 适用基线

- 正式工程：`H7_onboard_new_ps2 (2)(1)/H7_onboard`
- Git 基线：`7ceb308`
- 应用链接地址：外部 Flash `0x90000000`
- 调试串口：`UART8`，`PE1/TX`、`PE0/RX`、`115200 8N1`
- 烧录要求：必须使用工程现有的 Keil 外部 Flash 下载算法

本文只说明诊断和调参方法。未完成单腿验证前，不应修改步态公式、
连杆长度、舵机方向或 Leg5 专属补偿。

## 2. 腿编号和接口

```text
机器人前方

Leg4 (UART4)        Leg1 (USART1)
Leg5 (UART5)        Leg2 (USART2)
Leg6 (USART6)       Leg3 (USART3)

机器人后方
```

| 腿 | 位置 | 串口 | TX | RX | 数组索引 |
|---|---|---|---|---|---|
| Leg1 | 右前 | USART1 | PA9 | PA10 | 0 |
| Leg2 | 右中 | USART2 | PD5 | PD6 | 1 |
| Leg3 | 右后 | USART3 | PB10 | PB11 | 2 |
| Leg4 | 左前 | UART4 | PD1 | PD0 | 3 |
| Leg5 | 左中 | UART5 | PC12 | PD2 | 4 |
| Leg6 | 左后 | USART6 | PC6 | PC7 | 5 |

每条腿使用 ID 1、2、3 的三个串口舵机。Leg5 的诊断日志始终是六组
数据中的第五组。

## 3. 当前步态逻辑

### 3.1 控制循环

`LegControl_Task` 每个控制回合执行：

1. 读取 IMU 姿态和当前遥控输入。
2. 更新运动速度、机身位置和机身姿态。
3. 计算转动中心和步幅。
4. 为六条腿生成当前轨迹点。
5. 执行逆运动学，得到三个关节角。
6. 六路串口分别通过 DMA 发送三个舵机目标角，并轮询一个舵机反馈。
7. 按 `pace_time / N_POINTS` 补足本回合时间。

六条腿使用相同的控制回合和发送周期，没有 Leg5 专属的延时、速度或
步幅参数。

### 3.2 三角步态

- `N_POINTS = 100`，一个完整步态周期分为 100 个轨迹点。
- A 组：Leg1、Leg3、Leg5，相位偏移为 0。
- B 组：Leg2、Leg4、Leg6，相位偏移为 50。
- 两组相差半个周期，一组三腿摆动时，另一组三腿支撑。

Leg5 与 Leg1、Leg3 同相。如果 Leg1、Leg3 正常而 Leg5 明显滞后，
不能先归因于三角步态相位。

### 3.3 输入映射

行走模式中的有效输入：

| 输入 | 代码量 | 作用 |
|---|---|---|
| 右摇杆 RX | `Vx` | 左右横移 |
| 右摇杆 RY | `Vy` | 前进、后退 |
| 左摇杆 LX | `omega` | 原地或行进转向 |
| 左摇杆 LY | body Z | 调整机身高度 |

云端控制只模拟 `RY` 和 `LX`：

- 云端前、后对应右摇杆前、后。
- 云端左、右对应左摇杆左、右，即机器人左转、右转。
- 云端不提供横移，`RX` 保持为 0。

实体 `MODE` 键切换地形模式：

- 正常模式：抬腿系数 `0.7`，UART8 显示 `terrain=0 lift_pct=100`。
- 越野模式：抬腿系数 `1.4`，抬腿高度为正常模式的 2 倍，
  UART8 显示 `terrain=1 lift_pct=200`。
- MODE 不改变步幅、步态周期、三角/四角/五角相位或云端控制映射。
- PS2 的 MODE 不是普通按键位。驱动通过模拟/数字模式变化识别按键，
  检测后立即恢复模拟模式，避免摇杆持续失效。

## 4. 参数与动作关系

### 4.1 几何参数

| 参数 | 当前值 | 作用和风险 |
|---|---:|---|
| `LEG_LEN1` | 45 | 第一段连杆长度 |
| `LEG_LEN2` | 66 | 第二段连杆长度 |
| `LEG_LEN3` | 135 | 第三段连杆长度 |
| `CHASSIS_LEN` | 162.2 | 前后腿根间距 |
| `CHASSIS_WIDTH` | 161.5 | 左右腿根间距 |
| `CHASSIS_FRONT_WIDTH` | 93.3 | 前后端腿横向间距 |

连杆和机身参数直接进入正逆运动学，必须按实物旋转中心之间的距离
测量。原始工程的连杆参数为 `53/80/146.1`，与当前工程不同。这个差异
影响全部六条腿，不能作为 Leg5 单腿故障的直接解释。

### 4.2 步态参数

| 参数 | 当前值 | 增大后的主要效果 |
|---|---:|---|
| `KR_2` | 1.0 | 整体步幅增大 |
| `GAIT_LIFT_NORMAL_K` | 0.7 | 正常模式抬腿高度系数 |
| `GAIT_LIFT_OFFROAD_K` | 1.4 | 越野模式抬腿高度系数 |
| `MAX_R_PACE` | 60 | 允许更大的最大步幅 |
| `MAX_SPEED` | 115 | 允许更大的输入速度模长 |
| `PACE_TIME_DEFALUT` | 1000 ms | 完整步态周期变长，动作变慢 |
| `VELOCITY_FOF_K` | 见头文件 | 输入响应变快，但突变更明显 |

建议一次只改一个参数：

1. 先校准舵机零位和实物连杆尺寸。
2. 再以低步幅确认六腿方向和相位。
3. 调 `GAIT_LIFT_NORMAL_K` 保证正常模式脚尖离地。
4. 调 `PACE_TIME_DEFALUT` 确定速度。
5. 最后逐步提高 `MAX_R_PACE` 和输入响应。

### 4.3 零位和方向

- `LEG1_JOINT1_OFFSET` 到 `LEG6_JOINT1_OFFSET`：每条腿第一关节零位。
- `LEG_JOINT2_OFFSET`、`LEG_JOINT3_OFFSET`：六腿共用的第二、第三关节零位。
- 当前 `Leg::set_thetas()` 对六条腿的第三关节统一取负。

第三关节统一取负和原始工程不同，但当前用户确认整体步态可用。没有
实测六腿关节方向前，不应直接恢复原始写法。

## 5. BMI088 诊断

### 5.1 硬件接口

| 信号 | H750 引脚 |
|---|---|
| Gyro CS | PA3 |
| Accel CS | PA4 |
| SPI1 SCK | PA5 |
| SPI1 MISO | PA6 |
| SPI1 MOSI | PA7 |
| VDD/VDDIO | 3.3 V |

正常芯片 ID：

- Accel：`0x1E`
- Gyro：`0x0F`

### 5.2 UART8 日志

```text
[IMU] ok=... err=... id=AA/GG try=success/attempt
      hal=... spierr=... xfer=transfer/error miso=...
```

判定：

| 日志 | 含义 |
|---|---|
| `id=1E/0F ok=1` | 两部分均识别并完成初始化 |
| `hal=0 spierr=0 id=00/00` | HAL 传输完成，但 PA6 没读到有效返回，优先查供电、CS、MISO 和芯片 |
| `id=1E/00` | 加速度计通信正常，重点查 Gyro CS 或陀螺仪部分 |
| `id=00/0F` | 陀螺仪通信正常，重点查 Accel CS 或加速度计部分 |
| `hal!=0` | SPI HAL 自身报错，查 SPI1 状态和 HAL 错误码 |
| `miso` 长期固定且 ID 全零 | 只能说明采样时电平固定，需示波器或逻辑分析仪确认时序 |

初始化失败时 MPU 任务每秒重试一次，优先级低于步态任务。识别成功前
不再使用全零 IMU 数据执行姿态解算；普通遥控步态仍可运行。

## 6. Leg5 诊断

UART8 每秒输出以下五类六路统计：

```text
[LEGS_TX] start/done=...
[LEGS_TX_ERR] busy/err=...
[LEGS_RX] start/done=...
[LEGS_RX_ERR] count=...
[LEGS_FB] valid/invalid=...
```

每行顺序都是 Leg1 到 Leg6，第五组为 Leg5。

### 6.1 软件链路判定

1. `start` 与其他腿相近，但 `done` 明显少：
   检查 UART5 TX DMA、DMA1 Stream4 中断和 PC12。
2. Leg5 的 `busy` 或 `err` 持续增长：
   UART5 上一次传输没有正常结束，先解决串口状态。
3. `start/done` 正常，但 `RX done` 或 `FB valid` 明显少：
   检查 UART5 半双工切换、PD2、单线总线回读和舵机回复。
4. 六路发送和反馈计数接近，但 Leg5 仍弱：
   软件没有证据表明 Leg5 少发或晚发，应检查 8.4 V 压降、线束、
   接插件、舵机、关节阻力和安装零位。

### 6.2 最小交换实验

断电后把 Leg5 与一条正常腿的整套舵机总线和供电连接交换，不拆分单个
舵机：

- 故障跟随 Leg5 机械腿：检查舵机、供电支路、线束和机械阻力。
- 故障留在主控 UART5 接口：检查 PC12、PD2、方向控制和 UART5 链路。
- 交换后故障消失：重点检查接插件接触和线束压降。

交换实验前后都保存 UART8 的五组腿日志。没有这些证据时，不增加
Leg5 单独步幅、速度或角度补偿。

## 7. 直行左偏排查顺序

1. 架空机器人，确认六腿轨迹、相位和抬脚高度一致。
2. 比较六路 TX、RX、反馈统计，先排除 Leg5 通信异常。
3. 落地静止，测六腿三个关节的实际站立角和足端高度。
4. 低速前进，测 Leg5 供电端动态电压，不能只测主电源输出。
5. 做整腿线束交换实验，区分主控接口和机械腿故障。
6. 按实物复核连杆长度和六腿零位。
7. 最后才评估左右侧软件补偿。

`CEN_and_pace_cal()` 会把严格为零的速度量替换为很小的 `0.001` 以避免
除零。这是一个数学上的微小偏置来源，但现阶段没有证据证明它能造成
明显持续左偏。

## 8. 当前保护原则

- 不修改 PS2 和云端遥控指令层。
- 不修改六路串口映射和舵机发送周期。
- 不因 IMU 缺失阻塞步态任务。
- 不把 UART8、UART7 或 SC16 通道送入舵机半双工回调。
- 不使用未校验的舵机反馈 ID 作为数组下标。
- 先以日志和交换实验定位，再做 Leg5 专属补偿。
